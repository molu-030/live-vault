# Live Vault 3.9.5 — 스피커 녹음의 배경음 재유입 보강

개인용 `3.9.5-preview / versionCode 32`. 사용자가 스피커로 배경음을 들으며 녹음했다고 확인하여 디지털 믹스와 스피커→마이크 재유입을 구분해 점검했다.

## 원인 구분과 변경

기존 디지털 캡처·파일 반주·작곡기·기존 자동 반주는 보컬 DSP 뒤에서 합쳐진다. 이 경로가 보컬 에코/리버브를 통과하는 결함은 재현되지 않았다. 실제 production `Engine.render → beginRecord/stopRecord → WAV writer` 검사에서 네 경로의 배경음만 기록한 WAV는 극단적인 보컬 효과 ON/OFF에도 바이트가 같았다. 반대로 같은 배경음을 지연시켜 마이크 입력에 섞으면 보컬 효과가 적용되는 현상을 합성 입력으로 재현했다. 이는 실제 방에서 얻은 녹음이나 실제 기기 AEC 성능 측정은 아니다.

기본 오디오 모드에서는 실제 내장 스피커여도 입력에 `VOICE_RECOGNITION`을 사용하던 선택 정책을 보강했다. 별도 JNI 설정으로 AEC 선호/플랫폼 지원과 현재 내장 장치 ID를 전달한다. 다음 조건을 충족할 때만 입력을 `VOICE_COMMUNICATION` 및 입력의 보수적 성능 모드로 연다.

- 실제로 열린 출력 ID가 확인된 내장 스피커 ID와 일치한다.
- 명시적으로 선택한 내장 마이크이거나, 외부 입력 후보가 없는 기본 마이크이다.
- 사용자가 기기 AEC를 켰고 Android가 AEC 지원을 보고한다.

입력을 연 뒤 실제 입력 ID도 확인한다. 알 수 없는 입력/외부 입력으로 바뀌었거나 특수 입력을 열지 못하면 시작 전에 기존 음성 인식 입력으로 다시 연다. 기존 명시적 스피커·Bluetooth 모드는 유지한다. 이어폰/USB/외부 마이크/알 수 없는 출력/미지원/AEC 꺼짐 경로를 새 프로필로 추정하지 않는다. 시스템 음량·AudioManager 모드·출력 usage·보컬 효과 값과 디지털 배경음 믹스는 바꾸지 않는다.

입력 프로필은 실제 `AAudioStream_getInputPreset` 결과로 표시하며 기기 AEC 활성 상태와 구분한다. 프로필 설정은 다음 마이크 시작/경로 재개 때 적용한다. 기존 효과 배열이나 22개 통계 배열을 확장하지 않고 전용 JNI를 사용한다. 설정 복사/할당/잠금은 입력을 여는 제어 경로에서 수행하며 오디오 콜백에는 추가하지 않는다.

## 사용 확인

업데이트 후 마이크를 껐다 켜고 오디오 준비의 AEC 상태와 입력 프로필을 확인한다. 자동 기본 경로의 조건이 확인되면 `내장 스피커 에코 제어 입력`이 표시된다. 명시적 스피커 모드의 `음성 통신 입력`은 기존 경로다. AEC 활성 표시는 효과 객체의 활성 상태이며 완전한 음향 분리나 제거량을 보장하지 않는다.

디지털 배경음 원본은 효과를 우회하지만 스피커에서 이미 마이크로 섞여 들어온 소리는 보컬 입력의 일부다. 기기 AEC·방의 반사·거리·스피커 음량에 따라 잔여 재유입이 남을 수 있으며, 이번 작업에서 자체 음원 분리나 자체 방 음향 AEC를 추가한 것은 아니다. 외부 스피커나 지원되지 않는 장치에서 완전한 분리를 보장하지 않는다.

## 검사

`scripts/test-audio-buses.sh`는 AAudio 하드웨어 읽기만 stub로 바꾸고 실제 엔진/DSP/화음/정렬/파일 쓰기를 실행한다. 44.1/48kHz에서 네 디지털 소스, 보컬 효과 잔향, 스테레오·최종 클리핑, ±250ms 싱크, 클린 분석 입력, 스피커 재유입 대조 사례를 확인한다. 별도 시작 검사는 실제 production 마이크 열기를 통해 프로필 조건·실제 입력 확인·실패 복귀·실제 preset override·정리 상태를 확인한다. Java 검사는 정책·서비스 연결·상태 표시를 검사한다. 실기기 제거 성능·지연·음색 변화는 별도 확인이 필요하다.
