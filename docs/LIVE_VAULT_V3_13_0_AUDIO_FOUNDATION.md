# 3.13.0-preview — 오디오 파일·입력 클록·백엔드 기반

로컬 반주 파일 읽기, 녹음 파일의 저장·복구, USB 입력의 FIFO 보정, 읽기 전용 진단과 선택형 Oboe 비교 기능을 정리한다. 3.12의 매트 테마와 Material 3 간격·타입 규칙은 유지한다.

환경 교체 후 복원한 3.12 소스를 기준으로 이번 변경을 다시 구현했으며, 소실된 이전 작업을 그대로 검증된 결과로 간주하지 않는다.

## 로컬 반주 파일 읽기

파일 반주는 디스크의 PCM16 소스를 별도 읽기 작업자가 미리 읽는다. 캐시는 4,096프레임 × 8페이지 × 스테레오 float32로 **PCM 데이터 256KiB**를 담는다. 이 수치는 디코더·임시 파일·다른 오디오 버퍼를 포함한 전체 메모리 상한이 아니다. 네트워크 스트리밍 기능을 추가한 변경도 아니다.

오디오 콜백의 캐시 조회는 파일 읽기·탐색·스레드 합류를 수행하지 않는다. 탐색은 세대 번호로 이전 페이지와 구분한다. 재생 일시정지·EOF에서는 새 선행 읽기를 멈추고 작업자가 대기하며, 다시 시작할 때 필요한 위치를 준비한다. 이미 커널에서 진행 중인 파일 읽기를 강제로 취소하거나 모든 저장 장치에서 일정 시간 안에 끝낸다는 보장은 하지 않는다.

재생 중 필요한 페이지가 없으면 해당 반주 프레임은 무음으로 처리하고 재생 시계는 진행한다. 파일이 준비될 때까지 녹음·믹스 전체를 정지시키지 않는다. 부족 블록·부족 프레임·읽기 오류·캐시 준비량을 진단으로 확인할 수 있다. 캐시 크기 자체를 배터리 절감이나 끊김 방지의 실측 결과로 해석하지 않는다.

## 저장 확정 프레임과 복구

녹음 writer는 믹스와 보관 원음별로 실제 쓰기 결과를 확인한다. 파일 flush·동기화가 성공한 프레임까지만 journal의 확정 위치에 기록한다. Journal은 임시 파일 작성·동기화·이름 교체와 디렉터리 동기화를 거친다. 이 절차는 앱 수준의 복구 근거이며, 저장 장치의 전원 장애에도 데이터가 반드시 남는다는 보장은 아니다.

복구는 WAV 형식과 프레임 경계, 파일에 존재하는 데이터, journal에 확정된 위치를 함께 검사한다. 복구 결과의 오디오 길이는 확정 프레임에서 구하며 MIDI·영상·전송 시계와 다를 수 있다. 아직 확정되지 않은 끝부분을 버린 경우와 지원하지 않는 원음을 안내한다. 정상 파일과 손상 원음을 무조건 삭제하거나 정상인 것처럼 표시하지 않는다.

큰 파일의 복사·잘라내기·헤더 복구는 UI 스레드나 오디오 콜백에서 수행하지 않는다. 별도 복구 작업자가 디렉터리별 요청을 합치며, 테이크별 예약과 lease로 같은 파일의 편집·삭제·복구가 경합하지 않도록 한다. 교체 전 원본을 보존하고 메타데이터 반영이 실패하면 되돌린다. 앱 종료나 작업 중단 이후에도 다시 확인할 수 있도록 복구 표시를 유지한다.

보관함은 복구 중 상태를 표시한다. 복구 중인 테이크와 아직 무결성 확인이 끝나지 않은 테이크의 재생·복사·후편집은 차단한다. 복구 작업이 사용 중인 파일은 삭제하지 않으며, 실패 후 사용자가 원음이나 테이크를 명시적으로 삭제해 공간을 확보하는 경로는 유지한다. 영상 결합은 별도 작업에서 복구 완료를 기다리고, 오디오 복구가 끝나지 않으면 원본 영상을 유지한다. Writer의 누락 프레임·쓰기 오류는 실제 카운터로 보고하고 저장 문제를 정상 완료로 숨기지 않는다.

## USB 입력 FIFO와 장치 이탈

입력과 출력 샘플레이트의 명목 비율에 FIFO 점유량을 기준으로 한 완만한 보정을 더한다. 적응형 입력에는 약 **8ms의 알고리즘 목표 버퍼**가 추가된다. 이는 하드웨어 왕복 지연 측정값이 아니다. 경로·샘플레이트 변경 시 FIFO·위상·보정 상태를 다시 초기화하고, 입력이 부족하면 짧게 읽은 소리를 늘여 복제하는 대신 무음과 재준비로 처리한다.

진단의 ppm은 **FIFO 보정량의 추정값**이다. USB 장치의 하드웨어 클록을 타임스탬프로 실측한 drift 값이 아니다. 상태는 비활성·수렴 중·추적 중으로 구분한다. 목표 FIFO 프레임과 그 프레임 단위의 샘플레이트를 함께 내보내므로 버퍼 길이와 샘플레이트를 혼동하지 않는다.

입력 읽기 요청 미충족 프레임에는 선행 읽기 요청을 다 채우지 못한 양도 들어간다. 정상 입력 공급에서도 증가할 수 있으므로 실제 음성 손실로 표시하지 않는다. 추적 중 FIFO 부족으로 삽입한 무음 프레임은 별도 카운터이며, 초기 약 8ms 준비 구간과도 구분한다.

선택한 입력·출력 장치의 이탈을 감지하면 모니터를 끄고 진행 중 녹음을 마무리한다. 다른 마이크로 몰래 전환하거나 재연결 시 녹음을 자동으로 다시 시작하지 않는다. 다시 연결한 뒤 사용자가 직접 시작한다. 출력 이탈 시 관련 반주 재생도 멈춘다. 이 정책과 실제 USB 허브·케이블·오디오 장치에서의 동작 확인은 별개의 검증이다.

## 읽기 전용 진단과 JSON 저장

오디오 준비 화면의 상세 진단은 네이티브 캐시 스냅샷을 최대 1초 간격으로 읽는다. 진단을 열거나 저장하기 위해 마이크·카메라·녹음을 시작하거나 믹스를 바꾸지 않는다. UI가 실행 중인 스트림 포인터를 별도 조회하는 방식으로 진단을 구성하지 않는다.

| 항목 | 해석 |
|---|---|
| 출력·입력 xrun | 제공되는 실제 스트림 카운터; 미지원 값은 확인 불가 |
| 짧은 입력 읽기·요청 미충족 | 요청과 실제 읽기의 차이; 곧바로 실제 음성 손실을 뜻하지 않음 |
| 입력 FIFO 부족·초과 | FIFO가 채우지 못하거나 수용하지 못한 프레임 |
| FIFO 보정량·상태 | 점유량 기반 추정 ppm과 수렴·추적 상태 |
| 파일 캐시 | 부족 블록·부족 프레임·준비량·용량·읽기 오류 |
| Writer | 실제 누락 프레임과 쓰기 실패 작업 카운터 |
| 출력 버퍼·FIFO 목표 버퍼 | 알고리즘·버퍼 길이; 실제 왕복 지연과 구분 |
| 수동 녹음 오프셋 | 사용자가 저장한 보정값; 자동 지연 측정값이 아님 |

확인할 수 없는 값은 화면에서 `—`, JSON에서 `null`로 표시한다. 실제 왕복 지연은 `not_measured`, 실제 USB 장치 검증은 `pending`으로 유지한다. 경로·소스 재시작에 따라 카운터가 초기화될 수 있다.

사용자가 JSON 저장을 선택하면 Android 문서 선택기(SAF)로 저장 위치를 정한다. 선택 시점의 스냅샷은 화면 재생성 후에도 유지한다. 취소하거나 문서 제공자가 실패하면 다른 개인 저장 위치에 임의로 저장하지 않는다. JSON에는 파일 경로·장치 이름이나 주소·원음·다른 앱 정보가 포함되지 않는다. 요청한 백엔드·실제 백엔드·플랫폼 API·마지막 시작의 대체 이유는 구분해 포함한다.

## Oboe 선택형 비교

기본 백엔드는 기존 **직접 AAudio**다. 오디오가 완전히 멈춘 상태에서만 **Oboe 실험적 비교**를 선택할 수 있다. 실행 중 스트림·녹음·예약·연습·캡처·재생을 강제로 중단해 설정을 적용하지 않는다. Java와 네이티브에서 변경 가능 상태를 검사하고 네이티브 요청이 성공한 선택만 저장한다. 선택 자체로 오디오를 시작하지 않는다.

현재 Oboe 어댑터도 입력·출력에 **플랫폼 AAudio를 명시적으로 사용**한다. 따라서 “Oboe 선택”이 다른 플랫폼 API나 더 낮은 지연을 뜻하지 않는다. 양쪽 경로는 같은 render·입력 FIFO·DSP·믹스·writer를 공유한다. Oboe 열기·형식 확인·시작 실패 시 직접 AAudio로 대체할 수 있으며, 요청 값과 실제 적용 값, 플랫폼 API, 마지막 시작의 대체 이유를 각각 표시한다. 실기기 성능 우위를 주장하지 않는다.

## 최종 검증 결과 — 2026-11-10

이번 개인용 전체 Java/UI 회귀는 **55개 클래스·365개 검사, 실패 0·오류 0·건너뜀 0**으로 통과했다. 별도 대상 검사 44개는 이 전체 결과에 포함되며 중복해서 더하지 않는다. 새 검사에는 진단·백엔드 설정, 실제 파일을 사용한 저장 복구 9개, 장치 이탈·저장 오류 서비스 검사 7개, 비공개 캡처 수명주기 검사 10개가 포함된다.

한국어·영어 130% 글꼴에서 폰 412×893, 태블릿 1480×924, 작은 분할 창 960×600의 진단 화면 위·아래 12개 이미지를 Android 뷰/네이티브 Skia로 생성하고 주요 화면을 직접 검수했다. 합성 상태·기기 fixture를 사용한 렌더이며 실제 USB 음향 검사나 실기기 캡처가 아니다.

네이티브 검사는 bounded streaming·독립 journal·기존 44.1/48kHz 버스 분리, ASAN/UBSAN, 적응형 FIFO 및 실제 엔진의 합성 클록 변화·프레임 연속성을 포함한다. Oboe 엔진 검사는 하드웨어 어댑터만 대체하고 제품 Engine의 시작·대체·마이크 합류 실패·Harmony·FIFO·WAV writer를 실행한다. 계측한 콜백에서 메모리 할당과 mutex 호출은 0이었다. Android 빌드는 실제 공식 Prefab 어댑터와 공유 STL의 연결을 확인했다. 호스트 결과를 Android 하드웨어 성능이나 실제 USB 클록 측정값으로 해석하지 않는다.
