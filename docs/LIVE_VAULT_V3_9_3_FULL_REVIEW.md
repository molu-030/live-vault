# Live Vault 3.9.3 — 전체 검수와 경쟁 앱 비교

`3.9.3-preview / versionCode 30`, 개인용 APK. Sol medium으로 범위를 나눠 수정하고 루트가 변경 코드·공식 자료·기존 태블릿 렌더·최종 회귀 결과를 직접 검토한다. 이 버전은 검수에서 확인한 오류를 수정한다. [경쟁 앱 비교와 디자인/UI/UX/기능 제안](LIVE_VAULT_COMPETITIVE_REVIEW_2026_11_08.md)의 후속 믹서·저장 상태·화음 타일 등을 전부 구현한 버전은 아니다.

## 확인한 문제와 수정

| 영역 | 확인한 문제 | 최종 변경 |
|---|---|---|
| 영상 저장 | MP4 결합 뒤 보관함 정보 저장이 실패하면 원본과 최종 영상이 모두 삭제될 수 있었음 | 임시 MP4를 완성한 뒤 최종 경로에 게시. 보관함 정보까지 성공한 뒤에만 원본 삭제. 정보 저장 실패는 최종 MP4와 원본을 모두 보존하며 별도로 알림 |
| 저장 중 테이크 | 결합 중인 테이크의 이름 변경·삭제·공유·재생과 완료 작업이 충돌할 수 있었음 | 완료 전 테이크 메뉴/재생 차단, 기존 사용자 이름 보존, 실패 여부와 관계없이 완료 잠금 해제 |
| 파일 내보내기 | 시스템 저장 창에서 Activity가 재생성되면 내보낼 파일 참조가 사라져 빈 문서가 생길 수 있었음 | 선택한 원본 경로를 인스턴스 상태에 보존. 취소와 원본 없음은 명시적으로 알리고 대기 상태 초기화 |
| 보컬 연습 | 자동 종료 후 화면의 템포/기록 설정과 결과가 갱신되지 않을 수 있었음 | 활성→종료 전환에서 한 번 다시 그려 결과/설정을 복구. 스크롤 유지, 마이크 다시 시작하지 않음 |
| 긴 설정 시트 | 내용이 길거나 가로/분할 창·키보드로 높이가 줄면 저장/취소를 누르기 어려웠음 | 내용만 스크롤하고 제목과 48dp 저장/취소 행은 고정. 실제 가시 영역과 전달된 높이에 맞춰 재측정 |
| LLM 왕복 | 직접 기록한 뒤 자동 패턴으로 바꿔 보관한 프레이즈가 앱의 자체 내보내기 JSON인데도 재가져오기에서 거절됨 | 활성 여부와 별개로 같은 파트의 유효 트랙 ID를 허용. 없는 트랙과 나머지 스키마/제한 검사는 유지 |
| 프레이즈 표현 | 양자화로 짧아진 음의 이후 표현점이 다음 음에 적용되어 음정·강약이 바뀔 수 있었음 | 해당 음의 끝 및 파트 끝을 넘은 표현점은 재생하지 않음. 저장된 원래 곡선은 보존 |
| 프레이즈 출처 | 마이크로 기록한 트랙도 건반 직접 입력으로 표시하고 LLM 요약은 건반을 목소리로 표시 | 활성 프레이즈를 목소리/건반/구버전 기록으로 구분. 비활성 보관 프레이즈의 현재 자동 패턴 표시는 유지. 행의 불필요한 건반 이모지 제거 |
| 코드 모드 힙합 | 리듬 인덱스 8이 8행 배열 밖을 읽음 | 명시적 9번째 리듬 추가, 범위를 벗어난 인덱스는 기본 리듬으로 재생 |
| 입력 샘플 처리 | 스테레오/다른 샘플레이트 경로에서 입력이 짧게 읽히면 이를 출력 길이로 늘려 피치와 타이밍이 바뀜 | 사전 할당 FIFO와 연속 소수 위상으로 실제 비율 변환. 부족한 입력은 무음, 세션/오류 시 위상 초기화. 동일 레이트 모노 직접 경로는 유지 |
| 상태 조회 비용 | UI 통계가 필요할 때마다 전체 MIDI 노트 목록을 복사 | 개수만 읽는 경로로 변경해 불필요한 목록 복사/할당 제거 |
| TinySoundFont | 엄격 UBSan에서 음수 coarse 주소 오프셋의 signed left shift가 미정의 동작으로 검출됨 | 해당 한 줄을 범위가 안전한 signed 곱셈으로 변경. 경계값·전체 음원 region 주소·대표 PCM의 원본 동등성을 확인. 원본 라이선스/음원 파일은 유지 |

영상 코덱·AAudio·카메라·온라인 플레이어를 실제 기기에서 실행한 검증은 아니다. 영상 실패/파일 저장 검사는 실제 로컬 파일과 테스트 provider를 사용하되 코덱과 native 호출을 대체한다. 영상 파일의 원자적 게시 실패도 실제 파일 입출력으로 검사한다.

## 음악·화면·오디오 검증 기준

- Java/Robolectric은 기존 전조/스케일/파트/코드/트랙/드럼 즐겨찾기/파트 화살표/뒤로가기/팝업/종료/녹음/서비스/라우팅/AEC/YouTube/태블릿/언어 검사와 새 회귀를 함께 실행한다.
- 짧은 시트는 KO/EN × 기본/130% × 360×320/960×600dp에서 끝 항목 접근, 키보드와 유사한 높이 축소/복구, 고정 48dp 조작 행, 저장과 뒤로가기 취소를 확인한다.
- 프레이즈는 저장 데이터 불변, 비활성 보관 프레이즈 JSON 왕복, 연속 음과 파트 끝의 표현 범위, 한국어/영어 출처 표시를 검사한다.
- 네이티브는 44.1/48kHz, 8트랙+목소리, 정지 후 무음, 발음/재발음, 하울링 보호, 화음, 스테레오 짧은 읽기와 샘플 변환을 합성 입력으로 검사한다.
- 새 입력 변환기와 Composer는 ASan/UBSan을 사용한다. 처음 확인한 vendor signed-shift 진단과 수정 후 제외 옵션 없는 전체 통과를 구분해 [네이티브 결과](validation/v3.9.3/native.json)에 기록한다.

배터리·CPU·발열의 실기기 전후 수치는 측정하지 않았다. 이번 목록 복사 제거만으로 배터리 사용량이 얼마나 줄었는지 주장하지 않는다. 마이크가 꺼진 뒤 효과의 잔향까지 끝난 경로를 쉬게 하는 후속 설계는 경쟁 앱 비교 제안에 포함했다.

## 검증의 한계

실제 Galaxy Tab S9 Ultra/휴대폰의 터치·IME·One UI 확대, 음원 청감, 실제 가창, 장치 전환, Bluetooth/유선 왕복 지연, 스피커 AEC 제거량과 하울링 재발, 영상 인코딩·싱크, 장시간 부하는 기기에서 확인해야 한다. 합성 입력의 발음 검출 시간은 실제 유무선 청취 지연을 뜻하지 않는다. 기존 기기 AEC는 제조사 효과의 실제 활성 상태를 표시하며 자체 방 음향 상쇄 알고리즘을 새로 구현한 것은 아니다.

개인용 APK·서명 키·개인 캡처 오버레이·전달 URL은 공개 Git에 포함하지 않는다. 기존 공개 일반용 APK는 교체하지 않는다.
## 최종 검증 결과와 APK

전체 Java/Robolectric 234개 실행에서 232개가 통과했고, 남은 설정 시트/악기 선택 검사는 테스트 좌표·취소 콜백 처리·공유 세션 초기화 문제였다. 새 출처 표시 검사와 함께 fixture를 보완한 뒤 **시트·편집·악기 선택 20개**를 모두 통과했다. 클래스별 최신 결과를 교체하면 중복 제외 **234개 통과**이며, 234개를 한 번에 전체 통과한 실행을 뜻하지 않는다. [실행별 집계](validation/v3.9.3/coverage.json).

네이티브 DSP·Composer·하울링 보호·화음 및 새 입력 변환기 검사, 수정 후 제외 옵션 없는 Composer ASan/UBSan이 통과했다. TinySoundFont 275개 프리셋·13,098개 region의 주소 digest와 44.1/48kHz 대표 기타/베이스/피아노 PCM digest는 원본과 수정본이 일치했다. [명령·출력·기존 진단과 해결 결과](validation/v3.9.3/native.json). 기존 TinySoundFont의 offsetof 방식 관련 컴파일 경고는 별도로 남아 있다.
